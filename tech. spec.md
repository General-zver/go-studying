# Task Tracker CLI

## Техническое задание

**Название проекта:** Task Tracker CLI  
**Язык программирования:** Go  
**Тип приложения:** Консольное приложение (CLI)  
**Уровень сложности:** Beginner  
**Срок выполнения:** 3–7 дней

---

## 1. Описание проекта

Task Tracker CLI — консольное приложение для управления личными задачами.

Приложение должно позволять пользователю создавать задачи, просматривать их, отмечать выполненными и удалять.

Управление приложением осуществляется через командную строку.

Все задачи должны сохраняться в локальном JSON-файле. После завершения программы и повторного запуска ранее созданные задачи должны оставаться доступными.

### Цель проекта

Разработать приложение на Go, используя стандартную библиотеку языка.

В процессе разработки необходимо освоить:

- Структуры (`struct`).
- Срезы (`slice`).
- Функции и методы.
- Условные конструкции и циклы.
- Аргументы командной строки.
- Работу с файлами.
- Сериализацию и десериализацию JSON.
- Обработку ошибок.
- Основы тестирования.

## 2. Функциональные требования

### 2.1. Создание задачи

**Команда:**

```bash
go run . add "Изучить структуры Go"
```

**Ожидаемый результат:**

```text
Задача успешно создана! ID: 1
```

**Требования:**

- Каждая задача должна иметь уникальный числовой ID.
- ID должен генерироваться автоматически.
- Название задачи не должно быть пустым или состоять только из пробелов.
- При создании задача получает статус `todo`.
- Дата и время создания устанавливаются автоматически.
- Новая задача должна сохраняться в JSON-файле.

### 2.2. Просмотр списка задач

**Команда:**

```bash
go run . list
```

**Ожидаемый результат:**

```text
ID   TITLE                   STATUS
1    Изучить структуры Go     todo
2    Изучить срезы            todo
3    Написать CLI             done
```

**Требования:**

- Отображать ID, название и статус каждой задачи.
- Выводить задачи в порядке создания.
- Если задач нет, выводить сообщение:

```text
Список задач пуст
```

### 2.3. Изменение статуса задачи

**Команда:**

```bash
go run . done 1
```

**Ожидаемый результат:**

```text
Задача 1 отмечена как выполненная
```

**Требования:**

- Находить задачу по ID.
- Изменять статус с `todo` на `done`.
- Сохранять изменения в JSON-файле.
- Если задача уже выполнена, сообщать об этом.
- Если задача не найдена, выводить ошибку.

### 2.4. Удаление задачи

**Команда:**

```bash
go run . delete 2
```

**Ожидаемый результат:**

```text
Задача 2 успешно удалена
```

**Требования:**

- Находить задачу по ID.
- Удалять задачу из списка.
- Сохранять обновлённый список в JSON-файле.
- Если задача не существует, выводить ошибку.
- ID остальных задач не должны изменяться.
- ID удалённых задач не должны использоваться повторно.

### 2.5. Фильтрация задач

Приложение должно поддерживать фильтрацию задач по статусу.

**Показать невыполненные задачи:**

```bash
go run . list todo
```

**Показать выполненные задачи:**

```bash
go run . list done
```

**Требования:**

- `list` — вывести все задачи.
- `list todo` — вывести только невыполненные.
- `list done` — вывести только выполненные.
- Если задач с указанным статусом нет, вывести сообщение `Список задач пуст`.
- При неизвестном статусе вывести ошибку.

### 2.6. Справка по командам

Если приложение запущено без аргументов или с командой `help`, необходимо вывести информацию о доступных командах.

**Команда:**

```bash
go run . help
```

**Ожидаемый результат:**

```text
Task Tracker CLI

Доступные команды:

  add "Название"  Создать задачу
  list            Показать все задачи
  list todo       Показать невыполненные
  list done       Показать выполненные
  done ID         Завершить задачу
  delete ID       Удалить задачу
  help            Показать справку
```

## 3. Модель данных

Каждая задача должна иметь следующую структуру:

```go
type Task struct {
    ID        int       `json:"id"`
    Title     string    `json:"title"`
    Done      bool      `json:"done"`
    CreatedAt time.Time `json:"created_at"`
}
```

| Поле | Тип | Назначение |
|---|---|---|
| ID | int | Уникальный идентификатор |
| Title | string | Название задачи |
| Done | bool | Признак выполнения |
| CreatedAt | time.Time | Дата и время создания |

Значения статуса:

- `Done == false` — `todo`.
- `Done == true` — `done`.

## 4. Хранение данных

Для хранения задач необходимо использовать локальный файл `tasks.json`.

**Пример содержимого файла:**

```json
{
  "next_id": 4,
  "tasks": [
    {
      "id": 1,
      "title": "Изучить структуры Go",
      "done": true,
      "created_at": "2026-10-20T12:00:00Z"
    },
    {
      "id": 3,
      "title": "Написать CLI",
      "done": false,
      "created_at": "2026-10-20T14:30:00Z"
    }
  ]
}
```

Поле `next_id` хранит ID, который будет присвоен следующей создаваемой задаче.

### Требования к хранению

1. При запуске программа должна загружать данные из файла.
2. Если файл отсутствует, использовать пустой список задач и начальное значение `next_id = 1`.
3. При первом сохранении автоматически создавать файл.
4. После добавления, удаления или изменения задачи обновлять данные.
5. Для работы с JSON использовать пакет `encoding/json`.
6. Для чтения и записи файлов использовать стандартную библиотеку Go.
7. Если JSON повреждён, выводить ошибку и не перезаписывать файл.
8. Даты должны храниться в формате RFC3339.

## 5. Обработка ошибок

Программа должна корректно обрабатывать ошибочные ситуации.

| Ситуация | Ожидаемое поведение |
|---|---|
| Неизвестная команда | Вывести сообщение об ошибке |
| Не указано название | Сообщить, что название обязательно |
| Название состоит из пробелов | Отклонить создание |
| ID не является числом | Сообщить о неверном формате ID |
| ID меньше или равен нулю | Сообщить о некорректном ID |
| Задача не существует | Вывести сообщение об ошибке |
| Задача уже выполнена | Сообщить об этом |
| Неизвестный статус фильтра | Сообщить об ошибке |
| JSON содержит ошибку | Сообщить о невозможности чтения |
| Ошибка записи файла | Вывести понятное сообщение |

При возникновении ошибки приложение должно:

- Вывести понятное сообщение в `stderr`.
- Завершить работу с ненулевым кодом выхода.
- Не изменять существующие данные при ошибке чтения.

## 6. Структура проекта

Рекомендуемая структура:

```text
task-tracker-cli/
├── main.go
├── task.go
├── storage.go
├── task_test.go
├── go.mod
├── .gitignore
├── README.md
└── TASK.md
```

### Назначение файлов

**main.go**

Точка входа в программу. Обработка команд и аргументов командной строки.

**task.go**

Структура `Task` и функции для создания, удаления, изменения и фильтрации задач.

**storage.go**

Логика сохранения и загрузки данных из JSON-файла.

**task_test.go**

Автоматические тесты основной функциональности.

**go.mod**

Информация о Go-модуле.

**.gitignore**

Список файлов, которые не должны попадать в репозиторий. В частности, `tasks.json`.

**README.md**

Описание проекта, инструкция по запуску и примеры команд.

**TASK.md**

Техническое задание проекта.

Допускается другая организация файлов при сохранении разделения ответственности между компонентами.

## 7. Технические ограничения

При разработке необходимо соблюдать следующие условия:

1. Использовать язык Go.
2. Использовать только стандартную библиотеку.
3. Не использовать сторонние CLI-фреймворки.
4. Не использовать базу данных.
5. Не использовать глобальные переменные для хранения задач.
6. Разделять обработку пользовательского ввода, бизнес-логику и работу с файлами.
7. Обрабатывать ошибки с помощью стандартного типа `error`.
8. Использовать `gofmt` для форматирования кода.
9. Не игнорировать ошибки чтения и записи файлов.
